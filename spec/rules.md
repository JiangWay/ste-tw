# STE-TW 寫作規則

本文件包含核心原則、寫作規則和中英混寫規則。詞語選用見 [`word-choice.md`](word-choice.md)，名詞見 [`../glossary/`](../glossary/)。

## 和 ASD-STE100 的對應

| ASD-STE100 | STE-TW | 處理方式 |
| --- | --- | --- |
| 寫作規則（句子、程序、說明、標點） | 本文件第 2 節 | 直接移植，句長改用字數 |
| 核准字典（約 900 個英文詞） | `word-choice.md` | 改為繁中核准詞表 |

「80%」來自 Karpathy 的用法：規則從嚴，但是可以為了可讀性放寬。程序和規格不可放寬。

## 1. 核心原則

STE-TW 的所有規則都來自下面四個原則。如果規則沒有涵蓋某個情況，用這四個原則判斷。

1. **一詞一義**：一個詞只有一個意思。一個意思只用一個詞。不用同義詞變換文風。
2. **一句一事**：一句只說一件事。程序中，一句只有一個動作。
3. **主詞明確**：用主動語態。讓讀者知道「誰」做「什麼」。
4. **可以檢查**：寫可以被確認對錯的句子。用數字和名稱，不用「適當」「相關」這類模糊詞。

判斷方式：如果一句話可以有兩種理解，就重寫。

## 2. 寫作規則

規則分為五類：W 詞彙、S 句子、P 程序、D 說明、F 標點與格式。句長門檻是起始值：STE 程序句上限 20 個英文詞，換算成中文約 30 字，待實測校準。

**字數計算**：一個中文字算 1 字。一個英文詞、一個數字或一段 code 也算 1 字。標點不計。

### W 詞彙

| 編號 | 規則 | 不寫 | 改寫 |
| --- | --- | --- | --- |
| W1 | 只用核准詞表和名詞表的寫法 | 請配置資料庫連接 | 設定資料庫連線 |
| W2 | 一個詞只用它被核准的意思 | 驗證失敗（authentication 或 validation？） | authentication 失敗 |
| W3 | 不用虛化動詞：進行、作出、加以、予以、做（接名詞） | 對設定檔進行修改 | 修改設定檔 |
| W4 | 名詞串最多 3 個名詞，超過就拆開 | realm client scope mapper 設定問題 | client scope 的 mapper 設定錯誤 |
| W5 | 一個片語最多 2 個「的」 | 系統的設定檔的連線逾時的值 | 設定檔中的連線逾時值 |
| W6 | 不用文言和成語：之、其、乃、亦、皆、於、即 | 其值應小於之 | 這個值必須小於 30 |
| W7 | 不用模糊詞：相關、適當、一些、大概、基本上、等等 | 修改相關設定 | 修改 `application.yml` 的 `server.port` |
| W8 | 用台灣用語，不用中國大陸用語 | 調用接口獲取數據 | 呼叫 API 取得資料 |

### S 句子

| 編號 | 規則 | 不寫 | 改寫 |
| --- | --- | --- | --- |
| S1 | 用主動語態，不用「被」 | 設定檔被 Jenkins 覆蓋了 | Jenkins 覆蓋設定檔 |
| S2 | 寫出主詞。省略主詞會造成歧義時，不可省略 | 收到 token 後檢查 audience | Kong 收到 token 之後，檢查 audience |
| S3 | 不用雙重否定 | 不是不能重新啟動 | 可以重新啟動 |
| S4 | 代名詞（它、這個）只指前一句唯一的名詞。有疑慮就重複名詞 | Pod 連不到資料庫，它會重試 | Pod 連不到資料庫。Pod 會重試 3 次 |
| S5 | 條件和時間放在句首 | 重新啟動 Pod，如果 readiness probe 失敗 | 如果 readiness probe 失敗，重新啟動 Pod |
| S6 | 數字用阿拉伯數字，並加單位 | 等待三十秒左右 | 等待 30 秒 |
| S7 | 不用歐化結構：對於…來說、作為一個… | 作為一個管理者，你需要… | 管理者必須… |

### P 程序（指令）

| 編號 | 規則 | 不寫 | 改寫 |
| --- | --- | --- | --- |
| P1 | 一句最多 30 字 | — | — |
| P2 | 一句一個動作。只有「同時做」的動作可以放同一句 | 停止服務並備份資料庫後更新版本 | 1. 停止服務。2. 備份資料庫。3. 更新版本。 |
| P3 | 用祈使句，動詞開頭。不加「請」「您」 | 請您前往設定頁面進行確認 | 開啟設定頁面 |
| P4 | 每個步驟一個編號。編號順序就是執行順序 | — | — |
| P5 | 「警告」和「注意」放在步驟之前，不放在之後 | …執行 migration。注意：先備份 | 注意：如果沒有備份，資料無法還原。然後才寫步驟 |
| P6 | 預期結果另起一句 | 執行 `kubectl get pods` 確認都正常 | 執行 `kubectl get pods`。所有 Pod 必須是 `Running` |

「警告」用於人員、資安或法遵風險。「注意」用於系統或資料損失。「說明」用於不影響安全的補充資訊。

### D 說明

| 編號 | 規則 | 不寫 | 改寫 |
| --- | --- | --- | --- |
| D1 | 一句最多 40 字 | — | — |
| D2 | 一段最多 5 句，只講一個主題 | — | — |
| D3 | 第一句寫重點（結論先講） | 本文將介紹… | Token Exchange 讓中間層服務取得新 token |
| D4 | 描述事實不加時間詞。預期結果用「會」，不用「將」 | 系統將會自動進行重試 | 系統會自動重試 |
| D5 | 原因和結果分開寫，用「因為」「所以」連接 | 由於工作階段逾時故登入失敗 | 因為 session 逾時，所以登入失敗 |

### F 標點與格式

| 編號 | 規則 |
| --- | --- |
| F1 | 中文句子用全形標點（，。：、「」）。程式碼、指令、路徑、設定值用 code 格式 |
| F2 | 不用分號連接兩個句子。拆成兩句 |
| F3 | 重要資訊寫進句子，不放在括號裡。括號只用於第一次出現的英文原文 |
| F4 | 3 項以上的列舉用條列 |
| F5 | UI 上的文字用「」，照 UI 原文寫：按「儲存」。英文 UI 照英文寫：按「Save」 |
| F6 | 不用驚嘆號和刪節號 |

## 3. 中英混寫規則

基本原則：**名詞可以用英文，動詞和句子結構用中文。** 中文動詞保留句子結構，所以人和 LLM 都可以穩定解析。

### 何時保留英文

符合任一條件，就保留英文：

1. 產品、協定或標準的名稱。例如 Keycloak、OAuth 2.0、Entra ID。
2. 在程式碼、設定、log 或 UI 中原樣出現的詞。例如 Pod、timeout、realm。
3. 台灣沒有通用譯名，或譯名有歧義。例如 token、session、rollback。

台灣有通用且沒有歧義的譯名時，用繁中。例如伺服器、資料庫、憑證、快取。

### 規則

| 編號 | 規則 | 不寫 | 改寫 |
| --- | --- | --- | --- |
| M1 | 一個概念在整份文件中只用一種語言 | 前段寫 token，後段寫權杖 | 全部寫 token |
| M2 | 動詞用 `word-choice.md` 的中文動詞，不把英文動詞當中文動詞用 | 先 deploy 再 restart 一下 | 先部署，然後重新啟動 |
| M3 | 指令名稱例外：用 code 格式，前面加「執行」 | rebase 一下 | 執行 `git rebase` |
| M4 | 大小寫照官方寫法 | kubernetes、Postgresql、Github | Kubernetes、PostgreSQL、GitHub |
| M5 | K8s 資源類型照 API 寫法，用 code 格式 | 建立一個 configmap | 建立 `ConfigMap` |
| M6 | 中文和英文、數字之間加半形空格。全形標點旁不加 | 在Keycloak中建立3個client | 在 Keycloak 中建立 3 個 client |
| M7 | 英文名詞不加複數 s | 3 個 Pods | 3 個 Pod |
| M8 | 縮寫第一次出現時寫全名。API、URL、JSON、HTTP 不需要 | CA 沒有套用 | Conditional Access（CA）沒有套用 |
| M9 | 英文名詞不加中文譯名註解，除非讀者是非技術人員 | token（權杖）已過期 | token 已過期 |
