# 改寫範例

STE-TW 不一定減少 token。它刪除贅字，但是也會補上缺少的資訊，例如警告、數字和錯誤代碼。token 數用 o200k tokenizer 量測。

| 範例 | 改寫前 | 改寫後 | 變化 |
| --- | --- | --- | --- |
| 1. runbook 步驟 | 38 | 46 | +21% |
| 2. 對客戶的錯誤訊息 | 38 | 39 | +3% |
| 3. 說明段落 | 54 | 32 | −41% |
| 4. Copilot Studio 系統指令 | 90 | 50 | −44% |
| 5. OpenSpec requirement | 33 | 26 | −21% |

## 範例 1：runbook 步驟

**改寫前**：請先對 Keycloak 進行相關設定的備份，然後再去把 realm 匯出，之後如果發現有問題的話可以進行 rollback。

**改寫後**：

> **注意：** 如果沒有備份，設定無法還原。
>
> 1. 備份 Keycloak 資料庫。
> 2. 匯出 realm。
> 3. 如果匯出失敗，執行 rollback。

套用：W3 虛化動詞、W7 模糊詞、P2 一句一動作、P3 不加「請」、P5 注意放前面。token 增加，因為補上了注意事項和編號結構。

## 範例 2：對客戶的錯誤訊息

**改寫前**：抱歉，由於系統出現了一些異常狀況，您的理賠申請可能暫時無法被處理，請稍後再試。

**改寫後**：系統暫時無法處理您的理賠申請。請在 10 分鐘之後再試一次。錯誤代碼：CLM-503。

套用：S1 不用「被」、W7「一些」、「可能」、S6 數字加單位、對客戶用「您」和「請」。token 持平，但是客戶知道要等多久，客服也可以用錯誤代碼查詢。

## 範例 3：說明段落

**改寫前**：基本上，當使用者透過 SSO 登入之後，系統將會針對其 access token 加以驗證，若驗證不通過的話，則該請求將被 Kong 予以拒絕。

**改寫後**：使用者用 SSO 登入之後，Kong 檢查 access token。如果 access token 無效，Kong 回傳 HTTP 401。

套用：「基本上」、「將會」、「其」「該」、W3「加以」「予以」、S1「被」、「若…的話」、W2「驗證」。改寫前沒有說是誰驗證，改寫後主詞是 Kong。

## 範例 4：Copilot Studio 系統指令

**改寫前**：你是我們理賠部門親切又樂於助人的助理。請務必隨時以禮貌且清楚的方式回答問題。如果你對某件事不是很確定，希望你能讓使用者知道，並建議他們聯絡真人客服。盡量讓回答保持適度簡短，但如果額外的細節有幫助，也歡迎補充。

**改寫後**：你負責回答理賠部門的問題。保持禮貌。使用短句。不確定時，告知使用者，並請他聯絡真人客服。只在有幫助時補充細節。

套用：「務必」、「盡量」「適度」、D2 短句。系統指令每一輪都重送，所以節省會累積。

## 範例 5：OpenSpec requirement

**改寫前**：系統應該要能夠讓要保人去查詢自己的理賠案件，至於其他的人則是不行查詢的。

**改寫後**：系統必須只將理賠案件回傳給要保人或指派的理賠人員。

套用：「應該」改「必須」（SHALL）、「能夠」、「其」。改寫後要求可以直接轉成測試案例。
